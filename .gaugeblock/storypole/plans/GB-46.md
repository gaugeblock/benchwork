## 1. Executive Summary & Problem Statement

Benchwork provides a visual multi-panel workbench (Panel 1: Architecture & Docs, Panel 2: Backlog & Task Inspector, Panel 3: Synthesis & X-Ray, Panel 4: Foundry & Telemetry), but conversational AI currently resets on tab switching and lacks live workspace context awareness.

This specification defines the **Suite-Aware Chat Harness, Context Injection Engine, and Generative UI Copilot Rail**:
1. **Persistent Copilot Rail:** A persistent, collapsible right-hand split rail in `App.tsx` across all 4 panels powered by `@assistant-ui/react` (`useExternalStoreRuntime`), maintaining thread continuity and view context.
2. **3-Tier Context Injection Engine:** Pinned session identity (AGENTS.md, Mermaid rules, 9-Doc matrix), per-turn `<gaugeblock_environment>` XML radar envelope, and deterministic `@task:`, `@doc:`, `@symbol:`, `@crate:`, `/grill-me`, `/disentangle`, `/plan` expansions.
3. **8-Tool Dual-Partitioned Suite Traversal:** 4 Auto-Read tools executed autonomously within the Rust ReAct loop, and 4 Interactive Proposal tools emitting staged `ToolProposal` events requiring human approval cards.
4. **Generative UI Mutation Cards:** Modular React approval cards built with `makeAssistantToolUI` for decision holes, doc patches, and task plans.
5. **Resilient Dual-Mode Tool Parsing:** Native JSON tool calling with `<tool_call>` XML fallback and serde `deserialize_maybe_stringified` recovery for local GGUF / Single-Model Mode compatibility.
6. **Dual-Storage & Telemetry Training Spool:** Append-only `.gaugeblock/chat/threads.jsonl` with fast derived `.gaugeblock/chat/index.sqlite`, and automatic Silver SFT / Gold DPO spooling to `.gaugeblock/spool/outbox.jsonl` upon human proposal resolution.
7. **Zero-Recompile Prompts & X-Ray:** Runtime prompt templates in `.gaugeblock/prompts/*.md` and a live `[🔍 X-Ray]` turn inspector toggle in `CopilotRail.tsx`.

## 2. Resolved Architectural Decisions (`TaskDecision`s)

* **D1 (Frontend Generative UI Library):** Use `@assistant-ui/react` (`useExternalStoreRuntime` + `makeAssistantToolUI`) modeled after `assistant-ui/mastra-hitl` so backend tool proposals (`propose_decision_hole`, `propose_doc_patch`, `propose_task_plan`) map cleanly to modular React approval cards while keeping every `.tsx` file strictly ≤ 250 LOC.
* **D2 (Persistent Copilot Layout):** Make the Chat Copilot a persistent, collapsible right-hand split rail in `App.tsx` across all 4 panels that automatically receives the active panel's `UiViewportContext`.
* **D3 (3-Tier Context Injection Strategy):**
  1. *Tier A (Pinned Session Identity):* Repo overview, 9-Doc Separation of Concerns boundaries, Mermaid formatting guardrails, and `AGENTS.md` laws (modeled after Zed's `crates/agent/src/templates/system_prompt.hbs`).
  2. *Tier B (Per-Turn `<gaugeblock_environment>` XML Envelope):* Deterministic ~250-token snapshot of active branch, viewport focus, `.gaugeblock/storypole/` counts, `.gaugeblock/docs.toml` drift status, and active `sawhorse` model role (modeled after Cline's `getEnvironmentDetails`).
  3. *Tier C (Explicit `@`-Mentions & `/`-Commands):* Deterministic Rust expansion of `@task:<KEY>`, `@doc:<ARCHETYPE>`, `@symbol:<NAME>`, `@crate:<NAME>`, `/grill-me`, `/disentangle`, and `/plan <KEY>`.
* **D4 (Auto-Read vs. Staged Proposal Tool Boundary):** Read-only suite tools (`miter_inspect_scope`, `storypole_query_tasks`, `chalkline_check_drift`, `dado_preview_contract`) execute automatically inside the Rust ReAct loop; state-mutating tools (`propose_decision_hole`, `propose_doc_patch`, `propose_task_plan`, `trigger_joiner_run`) emit staged `ToolProposal` payloads requiring explicit human approval in the UI.
* **D5 (Resilient Single-Model Tool Parsing):** Support both native JSON tool calling and deterministic `<tool_call>` XML fallback, plus serde stringified-JSON recovery (`deserialize_maybe_stringified` modeled after Zed's `crates/agent/src/tools.rs`) so Single-Model Mode and local GGUF models never fail on nested tool arguments.
* **D6 (Dual Storage, SFT/DPO Spooling & Zero-Recompile Prompts):** Dual Storage in `.gaugeblock/chat/` (source of truth: `threads.jsonl`; derived fast cache: `index.sqlite`). When proposals are resolved in the UI: approved as-is emits Silver SFT trace to `.gaugeblock/spool/outbox.jsonl`; edited/rejected emits Gold DPO preference pair for rabbet (`planner_dpo.parquet`). Dynamic prompt templates loaded from `.gaugeblock/prompts/*.md` and a live `[🔍 X-Ray]` turn inspector toggle in `CopilotRail.tsx`.

## Section A: Phase 0 — Reference Architecture Investigation & Pattern Extraction (`Step H0`)

### 1. Frontend HITL Tool Cards & External Store Runtime (`assistant-ui`)
* **Repository:** `https://github.com/assistant-ui/mastra-hitl`
  * **File:** `components/tools/human-in-the-loop.tsx`
  * **Core Primitive:** `makeAssistantToolUI({ toolName, render })`
  ```tsx
  export const DecisionToolUi = makeAssistantToolUI<DecisionArgs, DecisionResult>({
    toolName: "propose_decision_hole",
    render: ({ args, result, status, addResult }) => {
      if (status.type === "complete") {
        return <ResolvedDecisionCard args={args} result={result} />;
      }
      return (
        <PendingDecisionCard
          args={args}
          onApprove={(chosen) => addResult({ approved: true, chosen })}
          onReject={() => addResult({ approved: false })}
        />
      );
    },
  });
  ```
* **Documentation:** `https://www.assistant-ui.com/docs/cloud/runtimes`
  * **Primitive:** `useExternalStoreRuntime`
  * Bridges custom `messages` store from `benchwork-cli` Axum backend into standard `ThreadMessageLike` items.
  * Handles asynchronous `onNew` stream reader over `/api/v1/chat/stream`.

### 2. Rust Inner Agent Loop & Axum Streaming (`block/goose`)
* **Agent Loop:** `https://github.com/block/goose/blob/main/crates/goose/src/agents/agent.rs` (`Agent::reply_internal`)
  * Turn limits enforced via `max_turns: u32 = 10` preventing infinite tool execution loops.
  * Cancellation token checks (`tokio_util::sync::CancellationToken`) on every streaming chunk.
* **Wire Protocol Contract (SSE Stream):**
  Bridged from Axum to frontend over `text/event-stream`:
  ```text
  event: text_delta
  data: {"delta": "Analyzing AST dependencies..."}

  event: tool_call_start
  data: {"call_id": "call_123", "tool_name": "storypole_query_tasks"}

  event: tool_result
  data: {"call_id": "call_123", "output": {"tasks": [...]}}

  event: tool_proposal
  data: {"proposal_id": "prop_456", "tool_name": "propose_task_plan", "payload": {...}}

  event: done
  data: {"total_tokens": 820, "turn_id": "turn_789"}
  ```

### 3. System Prompt Rules & Resilient Tool Deserialization (`zed-industries/zed`)
* **System Prompt Guardrails:** `crates/agent/src/templates/system_prompt.hbs`
  * Enforces orthogonal document boundaries (9-Doc Matrix), Mermaid syntax rules (strictly valid diagram types, quoted labels), and `AGENTS.md` laws.
* **Resilient Deserialization Helper:** `crates/agent/src/tools.rs`
  ```rust
  pub fn deserialize_maybe_stringified<'de, T, D>(deserializer: D) -> Result<T, D::Error>
  where
      T: serde::de::DeserializeOwned,
      D: serde::Deserializer<'de>,
  {
      let raw_value = serde_json::Value::deserialize(deserializer)
          .map_err(|e| serde::de::Error::custom(format!("invalid JSON: {e}")))?;
      
      match T::deserialize(&raw_value) {
          Ok(val) => Ok(val),
          Err(orig_err) => {
              let Some(s) = raw_value.as_str() else {
                  return Err(serde::de::Error::custom(orig_err));
              };
              serde_json::from_str(s).map_err(serde::de::Error::custom)
          }
      }
  }
  ```

### 4. Per-Turn Environment Radar Envelope (`cline/cline`)
* **Guide & Implementation:** `https://cline.bot/blog/system-prompt` & `getEnvironmentDetails` (`cline/cline#4364`)
* **Format:** Bounded strictly to ~200–250 tokens and tail-injected onto the user turn:
  ```xml
  <gaugeblock_environment>
    <active_branch>feat/gb-19-chat-harness</active_branch>
    <active_panel>Panel2_Backlog</active_panel>
    <focused_task>GB-46</focused_task>
    <storypole_summary ready="3" in_progress="1" blocked="0" />
    <docs_drift status="clean" checked_docs="9" />
    <sawhorse_role model="deepseek-v4.1-flash" active_preset="universal" />
  </gaugeblock_environment>
  ```

### 5. Dual Storage & Telemetry Training Spool
* **Disk Layout:**
  * `.gaugeblock/chat/threads.jsonl`: Append-only event log (`ThreadCreated`, `MessageAppended`, `ToolExecuted`, `ProposalCreated`, `ProposalResolved`).
  * `.gaugeblock/chat/index.sqlite`: Fast query cache (git-ignored) for thread lists, FTS5 message search, and proposal lookup.
  * `.gaugeblock/spool/outbox.jsonl`: Spools user approvals/rejections:
    * **Silver SFT:** Approved proposals logged with user intent + prompt + clean output.
    * **Gold DPO:** Edited/rejected proposals logged with prompt, rejected payload, and user-edited accepted payload for fine-tuning via `rabbet` (`planner_dpo.parquet`).
* **Zero-Recompile Prompts & X-Ray:**
  * Dynamic prompt templates loaded from `.gaugeblock/prompts/*.md` (with built-in fallback).
  * `[🔍 X-Ray]` turn inspector toggle in `CopilotRail.tsx` allowing developers to inspect exact assembled context and token budgets per turn.
