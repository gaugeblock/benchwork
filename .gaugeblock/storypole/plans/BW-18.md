# GB-66: Bulk Task Multi-Select and Batch Archiving in DagBoard

> **Status:** Ready  
> **Parent Epic:** `GB-64`  
> **Target Scope:** `benchwork` (`benchwork-core`, `benchwork-cli`, `benchwork/web`)  
> **Key Invariants:**  
> 1. Hard 250 LOC rule on all `.rs`, `.ts`, and `.tsx` files.  
> 2. Atomic multi-repo archive dispatch: batch archiving must resolve governing store per ticket (`ws.resolve_governing_store_name`).  
> 3. Zero orphaned UI state: bulk selection clears automatically after successful execution.  
> 4. Immediate WebSocket broadcast: live DAG updates notify all connected clients instantly.  

---

## 1. Overview & Objectives

In production workflows, managing hundreds of tasks requires bulk operations. Currently, tasks must be opened one-by-one in the drawer to archive them.

GB-66 accomplishes:
1. Adds `POST /api/v1/dag/bulk-archive` to `benchwork-cli` and `benchwork-core`.
2. Implements a multi-select state manager in `benchwork/web` (`useBulkSelection`).
3. Adds row checkboxes and "Select All" to `TaskTableView` (List view).
4. Adds card selection checkboxes and column-level select controls to `KanbanBoardView`.
5. Renders a fixed floating `BulkActionBar` showing selection count, "Archive Selected", and "Clear Selection" buttons.

---

## 2. API Contract & Data Types

```rust
// POST /api/v1/dag/bulk-archive
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct BulkArchiveRequest {
    pub task_ids: Vec<String>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct BulkArchiveResponse {
    pub archived_count: usize,
    pub errors: Vec<String>,
}
```
